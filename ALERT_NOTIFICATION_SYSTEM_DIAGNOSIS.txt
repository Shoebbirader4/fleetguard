PROBLEM SUMMARY
================================================================================

When you update an odometer reading that reaches/exceeds component expected life,
NO automatic alert or notification is being sent.

ROOT CAUSE:
-----------
The database trigger that fires when alerts are created needs the SERVICE ROLE KEY
to be configured in Supabase database settings. Without this key, the trigger
cannot call the alert-dispatcher edge function.

The two critical settings are NOT configured:
  ❌ app.settings.service_role_key (NOT SET)
  ❌ app.settings.supabase_url (NOT SET)

VERIFICATION QUERIES (Run in Supabase SQL Editor)
================================================================================

After configuring the settings, run these queries to verify:

-- Check if trigger exists and is active
SELECT tgname, tgenabled
FROM pg_trigger
WHERE tgname = 'trigger_alert_dispatch'
AND tgrelid = 'alerts'::regclass;

-- Check database settings
SELECT setting, value FROM app_settings 
WHERE setting IN ('app.settings.service_role_key', 'app.settings.supabase_url');

-- Check recent alerts
SELECT id, alert_type, severity, title, status, created_at
FROM alerts
WHERE created_at >= NOW() - INTERVAL '24 hours'
ORDER BY created_at DESC
LIMIT 10;

-- Check notification jobs
SELECT id, alert_id, user_id, channel, status, attempt, created_at
FROM notification_jobs
WHERE created_at >= NOW() - INTERVAL '24 hours'
ORDER BY created_at DESC
LIMIT 10;

-- Check cron jobs
SELECT jobname, schedule, command
FROM cron.job
WHERE jobname IN ('maintenance-scheduler-2am', 'notification-processor-1min');
